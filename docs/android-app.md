# Android app

17 November 2026. Work toward stages 6 and 7 of the [North America and Android plan](north-america-and-android.md). The renderer comparison remains in `proof/android`; the application is in `android` with its own install identity, `io.github.ianrastall.offlinemaps`.

## Offline transfer milestone

The desktop can export one installed region, including its prepared search index and whichever optional layers are installed:

```powershell
python -I tools/export-phone.py G:\Maps us-il D:\Transfers\Illinois
cargo run --release --locked -p offline-maps-dev -- verify-transfer D:\Transfers\Illinois
```

Choose a new output folder outside the map store. The export copies only active files, never in-progress downloads or obsolete versions. `transfer.json` lists each file's size and SHA-256. Copy the whole resulting folder to the phone over USB, then use Maps > Import map folder and select it through Android's file picker. No internet is needed. Desktop saved places are not part of a region transfer.

The shared Rust core verifies every listed file, the map's desktop checksum, Shortbread layers and coverage, SQLite integrity, the search index's association with that map, extras formats and optional layers. An imported region is activated by one directory rename only after verification. Cancellation or a failed check leaves installed regions and saved places intact. This first import format adds regions; it refuses to replace a region already installed. Updating imported regions and saved-place exchange remain later work.

Validation of this milestone: five transfer tests passed, including activation, cancellation, path rejection, checksum failure and preservation on duplicate import. The full workspace suite passed (104 tests). A real 945.3 MB Illinois export, including all optional layers, passed `verify-transfer`.

## Android 0.1.0 preview

Published 17 November 2026 as [android-v0.1.0](https://github.com/ianrastall/offline-maps/releases/tag/android-v0.1.0), built from `9a0a6e0b0397332b4d12acb5762463e5f630e0d2`. The signed APK is 127,815,671 bytes; SHA-256 `a93d8ace46d1af51c10acbc2a0e92b1b21c1f027c43c63eef2aca4b833b32cc2`, matching GitHub's asset digest. It is marked as a prerelease and leaves the Windows release as latest.

The first build has foreground satellite GPS, visible/used satellite counts while waiting, fix accuracy and age, follow mode, offline search and saved places. Android uses Kotlin/Jetpack Compose and the shared map page in WebView as Ian chose on 15 November. GPS fixes come from `LocationManager.GPS_PROVIDER`; no network provider or Play Services is required. A fix older than 30 seconds is shown as stale and cannot be saved as the current position. Direction is the GPS direction of travel when available, not a compass heading. Touching the map suspends following; Follow recenters on a fresh fix.

The app asks for precise location only when GPS is enabled, stops requesting fixes in the background and restarts when foregrounded. The manifest has no internet permission. Direct phone downloads are not part of this first build.

Build using the configured Android environment:

```powershell
. D:\lang\Enter-Lang.ps1
android\build.ps1 -Configuration Debug
android\build.ps1 -Configuration Release
```

Release builds use a persistent signing key under `%LOCALAPPDATA%\Jupiter\OfflineMaps\AndroidSigning`, outside Git. The password is protected for the Windows account with DPAPI. Keep the signing key and credential file for future installed upgrades. `dist` receives the APK. Android app versions are separate from Windows versions.

## Android 0.2.0: direct downloads

Published 17 November 2026 as [android-v0.2.0](https://github.com/ianrastall/offline-maps/releases/tag/android-v0.2.0), built from `34f3bc180500c11c1ef6f0ac16f8a5635e5d9a81`. The signed APK is 127,925,083 bytes; SHA-256 `bd2bd18d7b416b14691b4f8b8fe4944706025b5e1c38625a7e6f30ef2ebd9356`, matching GitHub's asset digest. The release includes a checksum file, is marked as a prerelease and leaves Windows 0.18.1 as latest. Install it as an update over 0.1.0; do not uninstall first. The signing certificate is unchanged.

Ian chose direct phone downloads as the next milestone on 17 November. The download browser lists the local catalog's 540 regions, searchable by region, country or continent, with approximate sizes and installed status. Maps > Download maps opens it; selecting an installed region in Maps opens its update controls. Maps include a search index built on the phone; stations/addresses, terrain and US overlays are separate optional downloads. Existing maps remain active while a replacement is downloaded and prepared.

Wi-Fi only is the default and is saved between launches. Each transfer is bound to its selected Android network, so a lost Wi-Fi connection cannot silently switch it onto mobile data. The setting can be disabled explicitly to permit a mobile-data transfer. Downloads run with the app in the foreground, keeping the screen awake; leaving the app or losing the selected connection pauses them. Resume probes the source and reuses verified resume metadata and staged bytes where possible. The unfinished region/layer is remembered across process restarts. There is one download at a time, with progress and cancellation through the same core as Windows. Storage is checked before downloading and again by the core against the actual remote file.

Android sets the new optional `Config.prepared_extras_only` flag. An unavailable or invalid prepared stations-and-addresses file produces an error rather than a raw-extract download/extraction. Windows keeps its existing fallback because the flag defaults to false. Android also builds its search databases beside their private destination; its global temporary folder is not writable by ordinary apps. The WebView still refuses remote origins; internet access is for the core's explicitly requested downloads.

The download details show each installed layer's date, including the flood effective date and overlay build date. Selecting an uninstalled region on the overview opens its download controls.

## Android 0.3.0: saved-place backups and preparation

Published 17 November 2026 as [android-v0.3.0](https://github.com/ianrastall/offline-maps/releases/tag/android-v0.3.0), built from `a5347630657c46cd7a18a62f87ab60d759249f64`. It uses the existing signing certificate and is verified installed on the Galaxy S26 FE. This Android preview leaves Windows 0.18.1 as the latest desktop release.

This milestone adds Saved > Add place for decimal latitude/longitude, names and notes; editing existing names/notes; filtering by either; and confirmed removal. Coordinates use north/east positive and south/west negative. Latitude must be -90 to 90 and longitude -180 to 180. The saved-place list identifies points outside installed detailed maps.

Saved > Export writes a JSON backup through Android's document picker. Saved > Import reads one, validates the entire file and previews the new/duplicate counts before confirmation. It merges without replacing existing places, reassigns imported IDs locally, preserves timestamps, and skips exact name/note/coordinate matches. Changed names or notes remain separate entries. A failed validation or write leaves both memory and the saved file unchanged. No network is needed. Backups include the user's coordinates and notes; they stay wherever the user chooses in the file picker.

The portable backup uses the same schema as the desktop's `saved-places.json`. Names are limited to 120 Unicode characters, notes to 2,000; lists to 10,000 entries and portable files to 16 MB. Unsupported schema versions, invalid coordinates/IDs and malformed JSON are rejected before committing any entry. The core commits an accepted merge with one atomic file replacement. A repeat import that adds nothing does not rewrite the file.

### Desktop exchange

The Windows UI is unchanged in this Android release. Close the Windows app before using this repository's checked command-line helper against its map store, so it cannot retain a stale in-memory place list. Substitute the actual store directory (shown in Windows Settings) for `G:\Maps`:

```powershell
# Export a new backup, then copy it to the phone over USB and choose Saved > Import.
cargo run --locked -p offline-maps-dev -- places-export G:\Maps D:\Transfers\desktop-places.json

# Copy a phone export over USB. Preview first; --apply performs the merge.
cargo run --locked -p offline-maps-dev -- places-import G:\Maps D:\Transfers\phone-places.json
cargo run --locked -p offline-maps-dev -- places-import G:\Maps D:\Transfers\phone-places.json --apply
```

Export refuses an existing output filename. Import preserves existing desktop entries and does not change map packages. Reopen the Windows app afterward to load the merged list. A desktop `saved-places.json` copied to a separate file can also be imported directly on the phone; never replace the active desktop file with a phone export to merge it.

## Android 0.4.0: downloads with the screen off

Published 17 November 2026 as [android-v0.4.0](https://github.com/ianrastall/offline-maps/releases/tag/android-v0.4.0), built from `55c1d88ff5edcbe723213445d1a3b248960e11c8`. The signing certificate is unchanged. It is an Android prerelease; Windows remains the latest desktop release.

Downloads now run in a user-started Android `dataSync` foreground service. Switching apps, turning off the screen or closing the map screen no longer pauses them. The service shows progress and Pause in a notification and posts a result when it finishes. Downloads no longer keep the display awake. A bounded partial wake lock keeps processing awake only while the service is working and is released on completion, pause, failure or service destruction.

The application session owns one native map store shared by map screens and the service. Screens register/unregister refresh listeners; destroying a screen releases its own worker and WebView without closing the store beneath an active transfer. A new screen attaches to the ongoing transfer. Wi-Fi only remains the default, sockets remain bound to the selected network, and connection loss pauses rather than switching an existing transfer to mobile data. No boot receiver or automatic retry was added. Force-stop/process death leaves staged data and the remembered region/layer for an explicit Resume after reopening.

Downloads offers Enable notifications in context. If permission or the channel is disabled, it explains that outside-app progress/Pause controls need notifications enabled. The transfer can still run with permission denied, as allowed by [Android's notification-permission rules](https://developer.android.com/develop/ui/compose/notifications/notification-permission); Pause remains in the app. Satellite GPS retains its existing foreground-only behavior.

On Android 15+, `dataSync` has a system background-time budget; the app implements the required timeout callback and immediately stops its service after requesting native cancellation. It also bounds each service run/wake lock to six hours. See [Android's timeout behavior and test controls](https://developer.android.com/develop/background-work/services/fgs/timeout). A stopped or interrupted operation can be resumed; installed data remains protected by the existing verification and atomic activation.

## Android 0.5.0: offline folder updates

Maps > Import map folder now copies and verifies the selected desktop export, then shows its region, size, map date and included layers before activation. For an installed region, the review compares its current map date with the folder date. An older transfer has a warning and an explicit Replace with older map action. Canceling the review discards the private copy. The original folder and saved places are untouched. Optional layers missing from the folder are kept.

Replacement uses fresh version directories for the map/search pair and every supplied layer. The existing readers continue using their old files while preparation and verification run. A journal records the previous pointer bytes before the short pointer commit. If a process stops before that transaction is marked committed, recovery restores the previous pointer set before opening readers or starting another map mutation. A committed transaction keeps the new set. Old versions are pruned only after the committed journal has been cleared; pruning now preserves every map version if the active pointer cannot be read. A 64 KiB reserve is released before recovery so small rollback writes have room if the volume fills after copying. Android also syncs the affected directories.

The import worker is separate from search/saved-place work. An application-session ownership flag prevents another screen from starting a competing map import/download while a previous import is finishing. Closing a screen cancels its import and schedules staging cleanup before releasing that ownership. Cancellation is retried while native work starts; once the short commit has begun it finishes consistently and reports success. Successful import refreshes every attached map screen through the shared session.
